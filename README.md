# 📊 Инструкция для ИИ-агентов (README)

Этот репозиторий предназначен для автоматического заполнения пятничного отчёта о трудозатратах ДИТ в Яндекс Формах с помощью Playwright. 

ИИ-агент (например, **OpenClaw**, **Hermes Agent** или любой другой LLM-помощник) должен использовать этот файл как руководство к действию для выполнения задачи пользователя по заполнению и отправке отчета.

---

## 🛠 Общий алгоритм работы для агента

### 1. Анализ запроса пользователя
- Выделите из запроса пользователя список категорий и процентов трудозатрат, которые необходимо проставить.
- Если проценты не указаны явно или в сумме не дают 100%, уточните их у пользователя или скорректируйте по правилам (если они заданы в контексте).

### 2. Подготовка конфигурации `config.toml`
- Проверьте наличие файла [config.toml](file:///g:/P7/apps/admin-tools/friday-report/config.toml).
- Если файла нет, скопируйте его из шаблона [config.example.toml](file:///g:/P7/apps/admin-tools/friday-report/config.example.toml) и заполните персональные данные:
  - `employee_name` — Имя сотрудника (как в форме Яндекса).
  - `department` — Подразделение (например, `"ОППО"`).
  - `browser_mode` — `"local"` (запуск локального браузера) или `"remote"` (удаленный через Browserless.io, требует указания `browserless_token`).
  - `debug` — установите в `false` для реальной отправки или в `true` для тестирования заполнения без отправки.

### 3. Изменение файла `workload.json`
- Основным интерфейсом ввода трудозатрат является файл [workload.json](file:///g:/P7/apps/admin-tools/friday-report/workload.json).
- Измените поле `"value"` у соответствующих категорий согласно задаче.
- **Критически важное правило**: Сумма значений `"value"` по всем ключам в [workload.json](file:///g:/P7/apps/admin-tools/friday-report/workload.json) должна быть **строго равна 100**. В противном случае скрипт завершится с ошибкой.

### 4. Запуск скрипта автоматизации
- Запустите скрипт с помощью команды:
  ```bash
  python friday_report.py
  ```
- Убедитесь, что процесс завершился с кодом `0`.

### 5. Верификация результатов по скриншотам
- После успешного прогона в папке `verified/` будут сохранены скриншоты процесса:
  1. `01_start_page.png` — Выбор подразделения и даты.
  2. `02_name_page.png` — Выбор сотрудника.
  3. `03_confirm_page.png` — Подтверждение отсутствия изменений.
  4. `04_workload_filled.png` — Заполненная форма перед отправкой.
  5. `05_final_page.png` — Результат отправки формы.
- **Обязательно**: Изучите скриншоты (особенно `04_workload_filled.png` и `05_final_page.png`), чтобы убедиться в правильности заполнения и успешности отправки.
- **Обязательно**: Отправьте/покажите эти скриншоты пользователю, чтобы подтвердить успешное выполнение задачи.

## 📄 Справочная информация по проекту

- **Язык разработки**: Python 3.11+
- **Основная зависимость**: Playwright (установка через `pip install playwright && playwright install chromium`)
- **Режим отладки**: Настраивается в `config.toml` (`debug = true/false`).
- **Скриншоты**: Сохраняются в `./verified/`.
