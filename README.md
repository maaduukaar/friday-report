# Friday Report

Telegram-бот и Playwright-исполнитель для заполнения пятничного отчёта. Основная версия рассчитана на команду до 300 пользователей.

## Хранение и изоляция данных

Для этой нагрузки используется SQLite (`data/friday_report.db`): отдельный сервер БД не нужен, а транзакции защищают профиль пользователя, недельный лимит и историю запусков от гонок. Включены WAL, внешние ключи и `busy_timeout`.

У каждого пользователя отдельно хранятся:

- Telegram user ID, личный chat ID, роль и статус доступа;
- ФИО, подразделение и трудозатраты;
- снимок профиля на момент запуска и статус отчёта;
- журнал административных действий.

`config.toml` больше не меняется из Telegram и содержит только общие параметры развёртывания/секреты. Скриншоты и JSON-снимок задания создаются в уникальном каталоге запуска, отправляются только его владельцу и затем удаляются.

## Установка

Требуется Python 3.11+.

```bash
pip install -r requirements.txt
playwright install chromium
```

Скопируйте [config.example.toml](config.example.toml) в `config.toml`, укажите адрес формы и обязательно задайте `telegram.bootstrap_admin_ids` — это Telegram **user ID** доверенного администратора, не chat ID.

Токен рекомендуется передавать через окружение:

```bash
set TELEGRAM_BOT_TOKEN=...
set FRIDAY_REPORT_BOOTSTRAP_ADMIN_IDS=123456789
python telegram_bot.py
```

На Linux используйте `export` вместо `set`. Допускается хранить токен и список начальных администраторов в `config.toml`, но файл должен быть доступен только учётной записи сервиса.

## Работа с пользователями

1. Администратор из `bootstrap_admin_ids` пишет боту `/start` — он создаётся с ролью `admin`.
2. Новый пользователь пишет `/start`, заполняет ФИО и подразделение через `/profile` и получает статус `pending`.
3. Администратор открывает `/admin`, проверяет заявку и подтверждает её.
4. После подтверждения пользователь редактирует только свои трудозатраты и отправляет только свой отчёт.

Бот принимает команды и callback-кнопки только из личного чата и авторизует по `from_user.id`, поэтому добавление бота в разрешённую группу не даёт её участникам доступ к чужим данным. Первый написавший боту человек никогда автоматически не становится владельцем.

Утверждённый профиль обычного пользователя заблокирован от самостоятельной смены: изменение ФИО/подразделения требует администратора. Это предотвращает подмену сотрудника после одобрения.

Для административного сопровождения доступны `/users`, `/block <telegram_user_id>` и `/setprofile <telegram_user_id>`; последние две команды позволяют отозвать доступ и скорректировать привязку к сотруднику без прямого доступа к БД.

## Недельный лимит отправки

В `/admin` есть настройка «Лимит отправок в неделю». По умолчанию он равен **1** и применяется отдельно к каждому пользователю в ISO-неделе выбранного `business_timezone` (по умолчанию `Europe/Moscow`).

Перед запуском браузера слот резервируется одной транзакцией SQLite, поэтому двойной клик и параллельные запросы не смогут обойти ограничение. В рабочем режиме:

- успешная отправка расходует слот;
- сбой до отправки формы помечается как неуспешный и позволяет повторить запуск;
- сбой после признака отправки получает статус «неопределённый» и сохраняет слот, чтобы не создать дублирующий отчёт.

При `debug = true` форма не отправляется, запуск имеет статус проверочного и лимит не расходуется.

## Запуск

```bash
python telegram_bot.py
```

По умолчанию одновременно выполняется только один браузерный отчёт. `telegram.report_workers` можно поднять максимум до 3, но для локального браузера безопаснее оставить 1. Очередь ограничена, поэтому 300 пользователей не создадут 300 процессов Playwright сразу.

Напоминание отправляется в пятницу после 17:50 по `business_timezone`. Факт напоминания хранится в БД, поэтому перезапуск в тот же день не рассылает дубликаты.

Для локального одиночного запуска по-прежнему можно выполнить:

```bash
python friday_report.py
```

В этом случае используются профиль и трудозатраты из `config.toml`.

## Миграция со старой версии

- Старый `allowed_chat_ids` намеренно не используется: он не различает роли и небезопасен для многопользовательского доступа.
- Перенесите только проверенные Telegram user ID в `bootstrap_admin_ids`.
- При первом `/start` первого bootstrap-администратора его старые `employee_name`, `department` и `[workload]` будут использованы как начальный профиль; другим пользователям они не копируются как профиль.
- `bot_state.json` больше не нужен. Не удаляйте его до проверки запуска, но он не влияет на новую версию.

## Безопасность и эксплуатация

- Храните `config.toml`, каталог `data/` и резервные копии БД с ограниченными файловыми правами; не добавляйте их в Git.
- Не включайте `session_replay` Browserless без согласования: запись сессии может содержать персональные и рабочие данные.
- Ротируйте Telegram/Browserless токены при подозрении на утечку; не передавайте их в чат и не пишите в логи.
- SQLite подходит для одного экземпляра бота на локальном диске. При нескольких экземплярах, сетевом диске или горизонтальном масштабировании перейдите на PostgreSQL и отдельную очередь задач.
- Делайте регулярные защищённые резервные копии SQLite-файла и проверяйте восстановление.

## Проверка хранилища

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют значение лимита по умолчанию, валидацию, независимость пользователей по ISO-неделям, конкурентное резервирование и лимит пользователей.
